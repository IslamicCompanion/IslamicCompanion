# Contributing to IslamicCompanion

Thank you for your interest in improving IslamicCompanion. Contributions of all sizes are welcome, including documentation, accessibility, bug fixes, and carefully reviewed feature improvements.

## Before you start

1. Check the existing README and project files to understand the current structure.
2. Search open issues and pull requests to avoid duplicating ongoing work.
3. For a significant change, open an issue first to discuss the proposed approach.
4. Keep changes focused. Avoid unrelated formatting or large generated-file updates.

## Development workflow

1. Fork the repository on GitHub.
2. Create a descriptive branch from `main`, for example `docs/improve-install-guide` or `fix/mobile-navigation`.
3. Make your changes in small, reviewable commits.
4. Test the affected part of the project before opening a pull request.
5. Push your branch and open a pull request against `main`.

## Website changes

For changes to the website:

- Check the page at both mobile and desktop widths.
- Verify navigation, download links, and external links.
- Check keyboard navigation and visible focus states.
- Use semantic HTML and provide meaningful alternative text for informative images.
- Respect the user's reduced-motion preference.
- Do not claim an app feature is available unless it is present in the project.

## Islamic content and references

Accuracy matters. Do not invent or paraphrase Quranic verses, Hadith, duas, prayer rulings, or religious citations. When changing Islamic content, include a reliable source and preserve the reference so maintainers can verify it. If a matter is disputed or outside your knowledge, ask the maintainers to review it rather than presenting it as settled.

## Pull request checklist

Before submitting, make sure that:

- [ ] The change has a clear purpose and stays within scope.
- [ ] Existing behavior has not been unintentionally broken.
- [ ] Links and assets added by the change work.
- [ ] The affected pages or features have been checked on a small mobile viewport.
- [ ] Documentation is updated when behavior or setup instructions change.
- [ ] No secrets, private keys, personal data, or unrelated build artifacts are included.

In your pull request description, explain what changed, why it is useful, and how you tested it. Include screenshots for visual changes where practical.

## Reporting bugs

When opening an issue, include:

- A short, descriptive title.
- The steps needed to reproduce the problem.
- What you expected to happen and what happened instead.
- Device, Android version, browser, or app version when relevant.
- A screenshot or log only when it is safe to share and does not contain private information.

Please be respectful and constructive in issues and reviews. Thank you for helping make IslamicCompanion more useful and reliable.
